## 結論

未編集のQwen3.5-0.8Bの内部MLP重みを変更し、推論時に口調を指定しない条件で「のだ／なのだ」の語尾が出るかを検証した。既存100問におけるレビュー判定の語尾成功は、未編集の0/100から編集後の15/100に増えた。新規50問では0/50から13/50（26%）だった。**既存100問で80%以上という目標は未達であり、ずんだもん口調の安定した定着は確認できなかった。**

ここでいう成功は、回答本文に自然な語尾接続と判定された文・名詞文が少なくとも1つあることを指す。内容の正しさ、質問への適合、反復は合否に使っていない。成功15件のうち14件が128トークン上限に到達しているため、15%を「自然な回答を最後まで生成できた割合」と解釈することはできない。

編集済みモデルは保存済みで、重みの変更範囲、元重みへの復元、再ロード後のハッシュと出力の一致を確認した。結果の根拠は[既存100問の集計](results/report.json)、[新規50問の集計](results/generalization_report.json)、[重みの検証記録](results/verification.json)に保存している。

## 目的と元実験との関係

目的は、プロンプトによる口調指定や生成後の文字列置換を使わず、Qwenの重み自体を編集して目標語尾を出すことである。元となるWeight-Space Programmingの実験8は、Qwenの内部挙動を観察し、仮説に基づいて重みを直接変更する研究である。本実験は、その方法を数学推論のループ抑制から日本語の語尾制御へ移した追試に位置づける。[元記事](https://rikiyat.github.io/blog/weight-space-programming/)・[固定コミットの実験条件](https://github.com/RikiyaT/lm_understand-logs/blob/4d09ba6d6a7e891dd8063974dfe81b3d78e3494f/exp8_math/README.md)

| 項目 | 本実験での扱い |
| --- | --- |
| 未編集モデルから開始 | 固定revisionの元checkpointを使用。過去実験の編集モデルを流用しない |
| 観察と直接介入 | 内部活性と重みを読み、方向・対象層・列・強度について仮説を立てて編集 |
| 学習の禁止 | backward、optimizer、損失へのフィッティング、教師あり最小二乗を使用しない |
| 編集対象の制限 | embedding、出力層、final normを変更せず、重み共有も維持 |
| 元実験から変更した条件 | 課題、データ、生成上限、thinking、デコード方法、推論環境と精度 |
| 再現していない条件 | CPU編集カーネルと推論サービスの分離、厳密なforward-pass予算、元の数学ベンチマークと数値結果 |

射影・外積・平均活性の計算には線形代数を使うが、回答例の誤差を最小化する回帰は行わない。最小二乗による更新と出力層編集の案は、元実験の制約を優先して実行前に撤回した。詳細は[実験プロトコル](PROTOCOL.md)を参照。

## 編集方法と探索結果

### 第1ラウンド 回答末尾の活性差

通常体と「のだ」体の同義回答を読ませ、末尾16トークンの残差・MLP活性の平均差を調べた。中盤以降で差の方向が比較的そろう層を選び、64列へのrank-one形式の書き込みを試した。

10候補の短縮評価はすべて0/10だった。初期層から方向のまとまりが約0.75と高く、口調を選ぶ処理よりも、異なる語尾を既に読んだ結果を捉えている可能性があったため、この測定に基づく探索を打ち切った。射影増幅は計画したが、このラウンドでは未実行である。[第1ラウンドの記録](results/round1_partial.json)

### 第2ラウンド 語尾を選ぶ直前の活性差

同じ質問・同じ回答prefixを、一般指示のみ／一般指示に口調指定を加えた条件で読ませた。prefixは通常体と「のだ」体のトークン列が共通する部分とし、回答開始・中間・分岐直前の活性を比較した。口調指定はこの観察時だけに使用した。

語尾分岐前の差のノルムは初期層では小さく、層23では約2.73に増えた。層15・17・16について、観察した方向への書き込みと、逆方向へ出力する列の成分抑制を比較した。teacher forcing時の目標トークンの相対確率は改善したが、自由生成の短縮評価では12候補とも0/10だった。50問で比較した3候補も自動検出は0/50だった。[活性の集計](results/prefix_summary.json)・[第2ラウンドの記録](results/round2_search.json)

### 第3ラウンド 語尾付近に働く書き込み

回答開始時・本文途中にも書き込むことが生成を乱すという仮説から、分岐直前の平均MLP活性を、開始・中間の平均活性が張る空間から直交化した。このkeyを使い、平均上は開始・中間への書き込みを抑える編集を作った。

層23・強度1ではレビュー判定が3/50（6%）、層15・19・23への分散編集・強度2では16/50（32%）になった。一方、高強度では「なのだなのだ…」の連続が増えた。そこで同じ第3ラウンド内で、目標語尾の末尾3トークンを既に読んだ位置の平均活性もkeyから除き、語尾後に書き込みを弱める修正を比較した。

### 保存した重みの変更

選択候補は、0始まりの層23、すなわち24番目のブロックの `model.layers.23.mlp.down_proj.weight` だけを変更する。形状は1024×3584である。

`d`を口調指定あり／なしの分岐直前の平均残差差、`g_branch`を一般指示だけで読んだ分岐直前の平均MLP活性とする。開始・中間・語尾後3位置の平均活性からGram–Schmidt法で正規直交基底`Q`を作り、次の差分を加える。

```text
k = g_branch - Q @ (Q.T @ g_branch)
ΔW = 8 × outer(d, k) / dot(g_branch, k)
W_edited = FP16(FP32(W_original) + ΔW)
```

この式では平均の`g_branch`に対して方向`8d`を書き込み、除いた平均活性への書き込みを抑える。個々の生成位置で同じ選択性が成り立つ保証はない。実際には反復や語中切断が多く残った。理論上の差分はrank-one形式で、FP16丸め後には3,638,144要素が元値から変わった。変更対象外の319パラメータテンソルは不変だった。[編集実装](contrast.py)・[検証記録](results/verification.json)

## 評価基準と最終結果

### 成功と数えた条件

本文に、自然な「のだ／なのだ」の接続と判断した文・名詞文が少なくとも1つあれば成功とした。たとえば「帰宅なのだ」は、質問に答えているかを問わず、名詞への語尾接続として成功に含めた。別の箇所に反復・誤り・破綻があっても、それだけでは失敗にしない。

単独の「のだ」行、引用内だけの一致、語中切断、「ですのだ」などの不自然な接続は除外した。評価はCodexエージェントによる回答単位のレビューであり、人間による独立評価ではない。既存の判定を集計したもので、この報告書作成時に合否や分母を変更していない。

## 解釈と限界

重みの変更によって目標語尾が一部に現れるようになったことは確認できた。一方、語尾前のトークン確率の改善や、平均活性に対する幾何的な選択性だけでは、自由生成での文法的な接続と終了を制御できなかった。

高強度の編集では語尾の出現とともに語中切断・反復が増えた。語尾後の平均活性を除く修正も、生成時のすべての状態で介入を止める仕組みにはならなかった。これらは観測結果に整合する説明だが、原因を一意に特定したものではない。選択方向が口調だけを表すことを確認するランダム方向対照や、独立した回路同定は実施していない。

候補選択に使った50問では36%、選択後の既存100問では15%だった。複数候補から選ぶことによる検証集合への適合や、質問構成の違いが寄与した可能性がある。新規50問も同じプロジェクトで作成したものであり、広い用途での汎化や統計的な優位性を示す結果とは扱わない。

今後同じ制約で続けるなら、実際の自由生成で語尾を選ぶ位置の活性を調べ、名詞・動詞などの接続を分けて観察すること、語尾を出した後の書き込み係数とEOSへの移行を測ることが次の検証候補になる。内容適合を合否に加える必要はないが、語尾の成立と正常終了は別の指標として残す必要がある。これらの追加実験は未実施である。
