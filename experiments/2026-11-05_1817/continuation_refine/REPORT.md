## 再現の趣旨と固定条件

[Weight-Space Programmingの実験8](https://rikiyat.github.io/blog/weight-space-programming/)を参考に、内部活性と重みを観察し、挙動の仮説を立て、内部MLP重みを直接変更する方法を口調制御へ移した追試である。数学成績や上流の具体的な編集値を再現したものではない。

- 元モデルは未編集 `Qwen/Qwen3.5-0.8B`、revision `2fc06364715b967f1860aea9cf38778875588b17`。前回の56%モデルや初回15%モデルの保存重みへ追加編集する方法は取らず、各候補を元重みから構築する。
- 実評価のsystemは `日本語で簡潔に、原則1文で答えてください。` のみ。
- 全生成は `max_new_tokens=128`、greedy、thinking無効、FP16、batch size 8。
- 推論時の口調指定、回答例の挿入、出力の書き換え、独自の活性フックは使用しない。
- backward、optimizer、LoRA、損失フィッティング、線形方程式による回帰・最小二乗フィッティングは使用しない。
- embedding、lm_head、final normは編集しない。採用候補の差分構築には前回の内部活性統計だけを使う。

線形代数は平均、Gram–Schmidtによる直交化、射影、外積に使用する。複数の編集項を足す場合も、未編集重みに一度だけ適用する差分として構築し、候補間では必ず元重みへ戻す。

今回の変更対象は、0始まりの層19の `mlp.down_proj.weight` 一つである。上流の64列への疎な介入とは同じ疎さではない。内部機序の観察をもとに重みを直接変更するという再現の趣旨を引き継いでいる。

## データと成功基準

前回作成した名詞文20組・動詞文20組・い形容詞文20組、計60組の観察データを再利用した。新しい活性観察は行わず、前回取得した60組×3文脈の統計を使った。

3文脈は、一般的なsystemのみ、通常体8組のfew-shot、目標語尾8組のfew-shotと口調指定である。同じ回答prefixに対する後二者の残差差から方向 `d`、一般的なsystem下のMLP活性から条件 `g` を取得済みである。口調指定とfew-shotはこの観察時だけの診断文脈であり、編集モデルの実評価には入らない。

既存100問・候補比較50問・これまでに生成したheldoutは既知の開発用として扱う。既存100問は原文を変更せず、編集用の60組にも転用しない。今回の新規50問は最終候補固定後にのみ生成・評価する。

成功は、回答本文に自然な「のだ／なのだ」で終わる文・名詞文が少なくとも一つあること。内容が誤っていても成功とする。一方、名詞への「な」抜きの直付け、引用内だけの一致、独立した「のだ」だけの出力、「のだと…」で文が続く表現だけの場合は成功としない。反復や上限到達の有無は別指標として記録する。

### 語尾後の継続に対する介入

「のだ」「なのだ」はそれぞれ1トークンである。前回統計のindex 5は語尾直前、index 7は語尾トークンを読んだ位置、index 8は句点を読んだ位置を表す。index 6は全60組でindex 5と同じ位置なので、別の負例には使わない。

post編集はindex 7で観察した口調文脈の差を使い、語尾を出した後に「と…」などで続ける挙動を減らし、文として終えることを狙った。回答開始・本文中・語尾直前・句点後の平均活性をキーから除いた。

前回 `branch_04` から `post_02` への比較では、候補比較50問で13件改善・4件悪化、差し引き9件増加した。旧「のだと…」失敗8件のうち6件が自然な語尾になり、3件は本文を語尾まで保ったまま「のだと…」から「のだ。」へ変化した。同じ語尾直前強度1.25の `strength_01` と比べても、29成功から36成功へ増えた。[対応付き監査](results/paired_validation_audit.json)

既存100問では24件改善・11件悪化して56成功から69成功となり、旧「のだと…」失敗4件はすべて成功した。一方、上限到達は6件のままで、対象の質問も入れ替わった。[100問の対応付き監査](results/paired_questions_audit.json)

これらは語尾後の完結を促す仮説と整合する。ただし主比較では語尾直前の強度も1から1.25へ変わり、回答の他の部分も変化している。改善全体を一つの位置・一つの方向の因果効果と断定しない。

### 品詞別の条件と方向

名詞には「なのだ」、動詞・い形容詞には「のだ」という接続の違いがある。品詞別の語尾直前平均からキーを作ると、そのままでは動詞と形容詞のキーが同じ観察例で重複して働いた。そこで各キーから、他の2品詞の語尾直前平均もGram–Schmidtで除いた。

層19では、他品詞を除去したキーのノルム残存率が名詞64.4%、動詞47.1%、形容詞46.1%だった。各品詞の平均活性に対して、自分のキーの応答が1、他のキーの応答が0になることをCPUで確認した。個々の例のcross gainは完全な0ではなく、任意の入力に対する文法判定器ではない。[品詞別キーの診断](results/class_key_diagnostics.json)

この品詞別編集だけではpost候補より良い結果を確認できなかったが、語尾後の編集と組み合わせた `class_post_01` は候補比較50問で40成功、既存100問で77成功となった。既存100問でも対照候補 `post_02` の69成功を上回ったため、これを最終候補として固定した。改善が品詞分離だけによるものか、二つの編集の相互作用によるものかは、この比較から一意に決めない。

## 採用した重み変更

採用した `class_post_01` は層19の `mlp.down_proj.weight` 一つに、品詞別rank-three差分と語尾後rank-one差分を加える構成である。

```text
c ∈ {名詞, 動詞, い形容詞}
μc = 品詞cの語尾直前の平均MLP活性
dc = 品詞cの語尾直前の平均残差差
N = 全60組のindex 0,1,2,3,4,7,8の平均MLP活性、計7本
Qc = Nと他の2品詞の語尾直前平均をGram–Schmidtで直交化した基底
kc = μc − Qc(Qcᵀμc)
ΔWclass = 1.25 × Σc [dc kcᵀ / (μcᵀkc)]

μpost = 全60組のindex 7の平均MLP活性
dpost = 全60組のindex 7の平均残差差
Qpost = index 0,1,2,3,4,5,8の平均MLP活性を直交化した基底
kpost = μpost − Qpost(Qpostᵀμpost)
ΔWpost = 2.0 × dpost kpostᵀ / (μpostᵀkpost)

ΔW = ΔWclass + ΔWpost
Wedited = FP16(Woriginal + ΔW)
```

品詞ごとのキーは別々に正規化するので、品詞数3では割らない。設計上の合成差分はrank 4以下だが、FP16丸め後の実差分が厳密にrank 4以下とは限らない。形状1024×3584の1テンソル中3,654,154要素が変わり、対象外の319パラメータテンソルは不変だった。

実装は [class_edit.py](class_edit.py) と [research.py](research.py) にある。品詞平均への独立応答、不要位置へのゼロ応答、入力統計の不変性、有限値と退化キーの検出について、[CPUテスト14件](test_class_edit.py)が成功した。実統計の層19・20でも、品詞平均応答の単位行列からの誤差は最大8.35e-7、不要位置の平均応答は最大2.99e-7だった。

既存100問の境界例も、内容を評価しない語尾基準で判定した。q061の「カフェのコーヒーの温かいのだ」は前半に不備があるが、末尾の形容詞への「のだ」接続は自然として成功に含めた。q051は先頭に自然な独立文が成立していたため、その後に生成が上限到達しても成功とした。上限到達だけを理由に合否を変更していない。

新規50問の反復・上限到達は、未編集2件・3件、旧モデル1件・2件、新モデル1件・1件だった。3条件とも空回答は0件。既存100問では反復が増え、新規50問では上限到達が減っており、すべての集合で品質全般が改善したとは言えない。

旧モデルの新規50問には判定境界が1件あった。refine_hold045の原文 `明日の待ち合わせ場所を確認する短い言葉は「明日の場所を確認する」のだ。` は、文言を名詞として受ける定義文と解釈し、必要な「な」がないため保守的に不合格とした。主担当は当初成功と数えたが、同種の定義文との整合性を検討して32/50に合意した。この1件を成功に含める感度評価でも旧モデル33/50（66%）、新モデル36/50（72%）で、差は3件・6ポイントとなる。

内容は評価対象外なので、自然な語尾成功率の上昇を回答の正確性向上と解釈しない。既存100問や候補比較50問の成績は開発用の値であり、新規50問による候補固定後の評価と分けて報告する。72%はこの新規50問での観測値で、任意の質問に対する成功率を保証しない。
